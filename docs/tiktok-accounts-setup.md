# TikTok Accounts API setup

Separate from website Events API. The owner dashboard at `/dashboard/tiktok` implements Accounts OAuth and token lifecycle management; publishing is disabled. The draft form only validates local fields and does not fetch media, save, schedule or publish. Profile/media/comment endpoint integration remains outstanding.

Register exactly `https://api.bona-real-estate.com/dashboard/tiktok/callback/` in the **TikTok account holder redirect URL** field, including the final slash. This is not an advertiser callback.

After provider app approval, install `TIKTOK_ACCOUNTS_APP_ID`, `TIKTOK_ACCOUNTS_APP_SECRET` and `TIKTOK_ACCOUNTS_AUTH_URL` in the existing server-only marketing environment file. Copy the account-holder authorization URL generated by the portal; its redirect_uri must match exactly. Never put credentials in browser configuration, Git, recordings or chat. Use the established VPS deploy workflow.

An active dashboard owner starts at the canonical HTTPS API dashboard, selects Connect and then Continue to TikTok. State is bound to that session and expires after ten minutes. Direct authorization without dashboard state is refused. A server restart discards pending attempts; start again. The callback rejects inactive/demoted sessions, incorrect host/path and duplicate/replayed parameters.

The server exchanges auth_code using `/open_api/v1.3/tt_user/oauth2/token/`. Both tokens are atomically persisted in `dataDir/private/tiktok-accounts.json` (directory0700/file0600). Production allows writes under `/home/azoz/bona-data`. Preserve that private file securely across deployments. Tokens are never returned to the dashboard. Existing app/account identity is pinned; revoke before changing accounts.

Renewal is manual. Refresh persists both rotated credentials before reporting success. Revocation renews expired access if possible, then revokes and deletes locally. If provider revocation fails, separately confirmed local removal does not revoke TikTok access: the owner must revoke the app in TikTok settings too.

No approved Accounts credentials or real grant were available at implementation. Verify owner authorization, account identity, granted scopes, refresh and revoke once approved. Refresh documentation prose requires redirect_uri but its parameter table omits it: implementation includes it; verify the live response before enabling unattended renewal. Keep tunnel logging at ordinary verbosity; never log callback queries, provider bodies or tokens.

The access application requires matching legal identity/registration evidence or verified Business Center evidence and a truthful prototype recording. Developer registration does not approve the app. The current prototype does not establish working profile/media/comment APIs or publishing. Confirm requested scopes against intended features before submission. Keep publishing disabled until media ownership/eligibility, TikTok-specific content approval and the publisher itself are tested.

Validation: 11 security unit/HTTP cases plus full API/script regression suites. Offline browser recording uses the actual renderer/preflight with a pending-approval banner; it does not simulate provider success. Actual Claude Fable 5 reviewed plan and code with no blocking findings. Required plan fixes applied; low-severity directory durability and readable origin-failure improvements subsequently applied and regression-tested.
