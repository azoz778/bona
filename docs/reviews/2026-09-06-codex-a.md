# Codex second-opinion review — intake (2026-09-06)

1. HIGH - Publish path rebases after writing repo changes: [pipeline.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/lib/pipeline.mjs:144), [index.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/index.mjs:190), [publish.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/lib/publish.mjs:33)  
   `processPdf()` writes images, inbox JSON, `_index.json`, and rebuilt `listings.json`, then `handlePdf()` calls `gitPull()`/`git rebase`. Git normally refuses rebase with unstaged changes, so normal publishes can fail and leave a dirty repo. Fix: pull and assert clean worktree before any repo write, or write into a temp/staging dir and atomically apply after pull; commit before push retry rebase, or use a clean worktree transaction.

2. HIGH - Edit commands mutate files before pull/commit: [edits.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/lib/edits.mjs:21), [index.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/index.mjs:238), [index.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/index.mjs:244)  
   `remove`, `hero`, `price`, `sold`, `hide/show` edit/delete local files first, then call `gitPull()`. Same dirty-rebase failure, plus `remove` calls `state.forgetPublished()` before the commit succeeds. Fix: pull/clean-check first, apply edit, rebuild, commit/push, then update state. On failure, restore from the pre-edit snapshot.

3. HIGH - Crash/failure can permanently drop a message and leave partial publish state: [index.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/index.mjs:82), [pipeline.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/lib/pipeline.mjs:169), [state.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/lib/state.mjs:38)  
   Messages are marked seen before processing, but `bySha256` is recorded only after push. A crash after repo writes but before push means the message will not be picked up again automatically, while the worktree may contain uncommitted listing files. Fix: track `pending/in_progress/completed` records by message id and sha; only mark terminal after successful reject or publish; on startup, recover/rollback dirty pending jobs. Also use a repo/state lock so a second daemon/manual run cannot race.

4. HIGH - Default-deny classifier has a broad false-accept for text-free private scans: [classify.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/lib/classify.mjs:67), [pipeline.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/lib/pipeline.mjs:78)  
   Any PDF with `<40` chars and enough embedded images is accepted as an “image-heavy design PDF”, so scanned IDs/contracts/invoices can reach Claude/contact sheets despite the README promise that private docs never reach AI. Fix: make text-free/image-heavy PDFs reject by default unless there is an independent property signal from owner caption/filename plus enough photo-like candidates; or OCR first and run the sensitive classifier on OCR text before any AI call.

5. MED - Image/PDF decoding lacks hard pixel and memory caps: [extract_pdf.py](/home/azoz778/bona-wt/wa-intake/services/intake/extract_pdf.py:171), [extract_pdf.py](/home/azoz778/bona-wt/wa-intake/services/intake/extract_pdf.py:197), [images.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/lib/images.mjs:31), [contact-sheet.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/lib/contact-sheet.mjs:32)  
   `doc.extract_image()`, `Pixmap()`, page rendering, and `sharp()` can decode very large images before rejection. The PDF byte/page caps do not stop decompression bombs. Fix: inspect image dimensions from `get_images()` before extraction, cap width*height and encoded bytes, cap rendered page pixels/DPI, use `sharp(input, { limitInputPixels })`, and set process/service memory limits.

6. MED - Prompt injection is mitigated structurally but not semantically: [claude.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/lib/claude.mjs:78), [prompt.md](/home/azoz778/bona-wt/wa-intake/services/intake/lib/prompt.md:94), [claude.mjs](/home/azoz778/bona-wt/wa-intake/services/intake/lib/claude.mjs:165)  
   Raw PDF text is appended after the instructions, and validation checks shape/copy hygiene, not whether price/specs/category facts came from trusted PDF/caption text. A malicious brochure instruction can still produce valid JSON with invented facts. Fix: explicitly wrap PDF text/metadata as untrusted data, require evidence fields for price/specs/location, and post-validate that numeric facts appear in caption or extracted text before publishing.

7. MED - systemd unit is not hardened around secrets and repo writes: [bona-intake.service](/home/azoz778/bona-wt/wa-intake/services/deploy/bona-intake.service:24)  
   The service runs with the user’s normal home access and no `NoNewPrivileges`, `PrivateTmp`, `ProtectSystem`, `RestrictSUIDSGID`, `LockPersonality`, or `ReadWritePaths`. Fix: restrict writes to `$BONA_REPO` and `$BONA_DATA`, make the rest read-only where possible, set `NoNewPrivileges=true`, `PrivateTmp=true`, `RestrictSUIDSGID=true`, `LockPersonality=true`, and add memory/process limits compatible with Node/Claude/uv.

8. LOW - Local image validator regex is broader than intended: [validate.mjs](/home/azoz778/bona-wt/wa-intake/scripts/curate/validate.mjs:39)  
   `LOCAL_STILL` accepts `/listings/foo.jpg` and nested `/land/foo/bar.jpg` shapes even though generated intake images are `/listings/<slug>/<nn>.jpg` and land stills are `/land/<name>.jpg`. This is not traversal, but it weakens the contract. Fix: split into exact `LOCAL_LAND` and `LOCAL_LISTING_IMAGE/THUMB` regexes.

I did not find message-controlled shell injection or path traversal in the slug/file paths: child processes use argv arrays, and generated slugs/image names are constrained. Owner-only authorization looks correct for normal Evolution group records, but I would still add live-shape tests for inbound non-owner group messages with `participant` set.
