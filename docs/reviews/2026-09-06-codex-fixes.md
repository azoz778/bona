# Codex regression review — fix commits 20aee26..b5131e4 (2026-09-06)

1. [services/api/index.mjs:416](/home/azoz778/bona/services/api/index.mjs:416) - HIGH - Daily budgets are charged before body parsing and before Retell/provisioning success. A caller with no `Origin` and `Content-Type: application/json` can send malformed JSON to `/v1/chat/session` or `/v1/call/token` and burn the global daily counters without spending Retell money. Fix: parse/validate body first, then charge immediately before the Retell call, or add a refund/commit-style budget API that only persists the spend after the request is valid and Retell is actually contacted/succeeds.

2. [services/intake/index.mjs:215](/home/azoz778/bona/services/intake/index.mjs:215) - HIGH - Duplicate protection is bypassed on replay because the guard requires `!retryPath`. `replayPendingJobs()` sets `retryPath` whenever the downloaded PDF exists, so a crash after publish but before `finishJob()` can replay the same PDF and publish a second listing. It is worse if the crash happens after `recordPublished()` but before `finishJob()`: even the state dedupe hit is ignored because `retryPath` is truthy. Fix: distinguish operator-requested retry from crash replay; never bypass SHA dedupe for replay. Also scan the pulled repo/inbox for `_intake.pdfSha256 === sha` before allocating a new ID/slug, because the repo is the durable source after a successful push.

3. [services/intake/lib/lock.mjs:42](/home/azoz778/bona/services/intake/lib/lock.mjs:42) - HIGH - A stale lock is stolen even when the holder PID is still alive. Any long AI/render/build/push run over `staleMs` lets another daemon/run-once process remove the lock and enter the repo phase concurrently, which can interleave pulls, writes, resets, commits, and pushes. Fix: only steal when the holder is dead or the lock is malformed and demonstrably ownerless; if live holders need stale protection, heartbeat/touch the lock while held and timeout waiters instead of stealing live locks.
